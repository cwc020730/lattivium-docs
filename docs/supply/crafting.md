# 合成与物资账目

合成把实际携带的原料转换为需求物品。配方事实、数量规划、原生操作和用途结算分别具有明确职责。

## 配方与批次

| 术语 | 具体含义 |
| --- | --- |
| 配方事实 | 游戏提供的输入槽位、允许原料、输出与合成网格要求 |
| 配方目录 | 按产物查询可用配方的集合，由 Atlas 提供 |
| 配方展开 | 从缺少的成品追溯所需原料，选择允许的原料与配方 |
| 合成批次 | 一种配方执行的次数及这一批所需输入、预计输出 |
| 原生合成 | Bot 实际在背包或工作台菜单中放原料并取出产物 |
| 余料 | 满足最终需求后仍实际持有的原料或多出的产物 |

例如一个原木的配方产生 4 个木板，需求 6 个时需执行两次、消耗 2 个原木、产生 8 个木板。6 个分配给最终目标，2 个保留为余料。

## MaterialProductionPlanner

**输入：**最终需求、允许使用的库存数量、配方目录、工作台能力和规划预算。

它优先使用可提供的库存，缺少的部分尝试配方展开，形成有顺序的批次与缺口说明。规划输出记录 `finalDemand`、`usedStock`、`crafts`、`allocatedFinal` 和 `shortfalls`。

默认单次限制为深度 12、展开 10000 次、规划计时约 100 ms；累计任务限制为 16 次规划、50000 次展开、约 500 ms。这些限制约束规划工作量，实际旅行和合成另有执行预算。循环、缺配方、组件输出不支持或预算耗尽会形成具体缺口原因。

## AcquireProductionFlow

**输入：**已准备的收集请求、候选生产计划、来源重选服务和任务预算。

```text
CollectSupplyFlow：收集来源物资
  → 核对实际持有原料和取得回执
  → 按实际可用原料重新规划可执行合成
  → ProduceCarriedMaterialsFlow：执行批次
  → 结算最终用途、余料、缺料和未结责任
```

当前主线先完成收集阶段，再根据实际取得量规划并执行生产。工作台工具准备等子操作还可以获取自身需要的物资。

**结果：**实际分配给最终目标的 `available`、缺少的 `missing`、旅行信息、来源失败与 `settled` 状态。`fulfilled()` 要求已经结算、缺量为空且没有生产失败。调用者据此选择交付或继续施工。

## ProduceCarriedMaterialsFlow

若所有批次都适合背包 2×2 网格，调用 `ExecuteProductionFlow`。存在需要工作台的批次时，通过 `AccessCraftingTableFlow` 选择作业位置，再由 `CraftAtTableFlow` 执行。

现有可用工作台可供访问；临时工作台需要准备、放置并在结束时回收。`PrepareCraftingToolFlow` 在共享来源和有限生产预算内准备所需工具物资。`CraftBatchFlow` 推进具体配方的原生菜单操作。

合成完成以实际产物和原料消耗为依据。未归还的临时工作台、菜单中的待恢复物品或库存差异会保留恢复责任。

## MaterialLedger

物资账目区分实际持有量和不同用途的预留：

| 用途 | 预留意义 |
| --- | --- |
| `FINAL_CARGO` | 最终要交付或交给调用者使用的物品 |
| `INGREDIENT` | 合成将消耗的原料 |
| `TOOL` | 作业工具、临时工作台等用途 |
| `TRAVEL` | 飞行及旅行资源 |
| `FOOD` | 进食资源 |

可用量为实际持有量减去所有用途预留。一次操作先预留，再以实物消耗、产物和归还结果结算；交付还需要实际转移证据。

例如同一份火药可以作为计划材料，也可以制造烟花。用途预留约束这两种消费，防止把同一份物资重复计入不同目标。恢复时也会核对这些预留与真实库存。
