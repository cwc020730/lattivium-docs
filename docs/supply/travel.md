# 来源访问

来源访问负责把一个来源分配推进到实际取货。它保存容器身份、分配数量与失败回执，调用旅行到达来源，再调用容器组件完成交互。

## 来源位置与访问目标

`SourceJob` 指向一个维度中的容器方块，并指定物品和数量。访问容器需要找到 Bot 能站立、触及目标且交互射线有效的位置。

例如箱子位于 `(100,64,100)`，Bot 可以站在旁边可交互的格子。容器坐标用于识别库存；旅行的脚位和到达条件见[目的地与到达条件](../navigation/targets)。

## SupplySourceFlow

**输入：**一个 `SourceJob`、执行请求及可选容量恢复操作。

```text
核对目标维度
  → TravelToFlow：接近来源
  → AcquireContainerItemsFlow：访问并取得分配物品
  → 返回实际取货回执
```

它拥有一次来源尝试的旅行与获取过程。来源接近阶段允许预算内的替代路线；在尚未转移物品、已落地且清理完成的边界，可以重新规划接近或转交上层换源。

补给改变 Bot 位置后，流程按实际新位置重建旅行和精确访问。部分取得和借盒责任保存在取货回执中，失败后由拥有这些状态的流程处理。

**输出：**单个来源的实际取得或失败记录，以及尚需完成的恢复责任。

## 旅行的调用边界

来源业务向 `TravelToFlow` 提供维度、参考位置和接近条件。旅行选择同维度或跨维度路线并返回实际到达位置；随后取货流程核验容器交互。

旅行复用调用者提供的烟花和食物策略。路线、穿门、局部移动及飞行分别见[寻路与旅行](../guide/navigation)，维护触发和恢复见[补给与执行恢复](./maintenance)。

## AccessContainerFlow

**输入：**当前维度的容器方块位置及访问策略。

它搜索有效交互站位，按需接近区域、局部寻路和对齐，再调用 `OpenContainerFlow`。现场会核对容器、人物净空、距离、射线和开启空间。

**完成条件：**目标实体库存对应的菜单已经实际打开，并提供 `OpenContainerResult`。后续物品转移由[容器取货组件](./containers)执行。

## 区块观察与不可达

Atlas 可以记录尚未加载区域的容器，实际访问仍需要观察对应地形。未知地形、无支持站位、路线预算耗尽和来源保护分别影响访问结果。观察和搜索预算见[旅行异常](../navigation/recovery)。

“不可达”表达当前策略及预算内无法完成访问。上层记录来源坐标与原因，尝试替代或报告缺料；具体处理见[交付与结果](./delivery#缺料与失败)。

`netherRoofOnly`、结构排除及来源保护会减少可选路线或库存。配置见[配置选项](../reference/config)。
