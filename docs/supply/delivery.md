# 交付与结果

物资获取完成后，调用者决定把材料交给指定容器，或保留在 Bot 身上继续施工。结果同时表达实际转移量、缺料和未结责任。

## 交付目标与返回位置

| 目标 | 语义 | 完成依据 |
| --- | --- | --- |
| 交付目标 | 维度与实际容器方块坐标 | 物品已转移并通过数量核验 |
| 返回位置 | 维度与 Bot 脚位 | Bot 满足目标到达条件 |
| 施工目标 | 获得的材料随后用于指定场地 | 施工自身的设施和区域核验 |

`AtlasSupplyTask` 拥有交付义务；`AcquireMaterialsFlow` 将材料留给调用者使用，支持最终返回位置。参数入口见 [Task 参考](../reference/tasks#atlassupplytask)。

## ProductionSupplyFlow

它先推进 `AcquireProductionFlow`，得到实际可分配成品，然后把这些已携带物资交给 `SupplyFlow` 运输和交付。

允许结算的部分取得会保留实际货物及缺料记录。生产阶段若记录失败，交付已有成品后仍报告该生产失败，并带上确认交付量与剩余需求。执行终态和物品交付量需要分别查看。

## SupplyFlow

它管理收集、打包、交付及核验的顺序。调用者可提供来源任务，或提供已携带的货物直接进入后续阶段。

`DeliverSupplyFlow` 负责访问目标容器和实际转移，`VerifySupplyDeliveryFlow` 根据交付清单与回执核对结果。打包依执行请求决定；容量恢复可以在支持的路径中先交付一部分货物，再接续来源收集。

交付容器需要可访问且有相应容量。多个目标由请求声明，分配和实际交付位置记录在结果中。

## 数量词典

| 数量 | 含义 |
| --- | --- |
| 需求 | 本次最终要满足的数量 |
| 分配 | 规划安排使用的来源与携带数量 |
| 取得 | 实际取货确认的数量 |
| 合成产出 | 原生合成实际得到的数量 |
| 持有 | 当前观察到的携带库存 |
| 最终用途预留 | 持有物资中已经划给本次目标的数量 |
| 交付 | 实际转入目标容器并确认的数量 |
| 未分配 | 当前计划没有安排来源的部分 |
| 取得失败 | 已安排来源但预算内未能取得的部分 |
| 最终缺料 | 最终目标仍未满足的数量，由结算结果确定 |

例如需求 64 个石头、计划分配 64 个、现场取得 48 个并交付 48 个，结果应保留 48 个实物交付与剩余 16 个缺口。步骤完成数与这些物品数量分别表达流程进度和物资结果。

## 缺料与失败

来源失败后，收集流程在预算内查询替代。没有可用替代时，记录物品、数量、来源维度、坐标与原因，再处理已有货物和剩余责任。

交付业务可以报告带缺料的完成结果。施工的开工前获取要求 `fulfilled()`，需求未齐时阻止开工。借盒未归还、库存不一致、未结工具或清理失败保留独立失败责任。

来源的“不可达”取决于实际访问策略和搜索预算。记录支持以后人工复核，详见[来源访问](./travel#区块观察与不可达)。

## 执行模式

| 模式 | 物品与世界行为 |
| --- | --- |
| `REAL` | 实际取得和交付，减少来源库存 |
| `DEBUG` | 验证旅行与容器访问，物品转移被跳过 |
| `SOURCE_PRESERVING_DEBUG` | 复制取得物品，来源库存保留；交付、施工和临时设施仍实际改变世界 |

跳过转移的调试回执具有相应效果状态。实物交付验收使用实际库存及转移回执。

## 查询结果

提交受理后返回任务 ID。使用 `/ltv Worker status <taskId>` 查询该次执行，结合业务回执查看交付、缺料、来源失败与未结责任。

Trace 用于观察调用链、条件和位置；核验结果结合真实库存、容器与世界状态。状态语义见[状态与错误码](../reference/failures)。
