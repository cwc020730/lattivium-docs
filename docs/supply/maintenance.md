# 补给与执行恢复

资源维护是当前执行拥有的子操作。检查点恢复则在重新上线或重新提交时核对保存状态，继续支持恢复的业务。

## 维护术语

| 术语 | 具体含义 |
| --- | --- |
| 资源策略 | 决定何时补给、需要多少、从哪里取得的规则 |
| 维护片段 | 一次有预算的补给子操作，可包含旅行、拆盒和取得物资 |
| 安全边界 | 可以结算库存并开始进食、补给或等待的操作状态 |
| 库存下限 | 可用量低于此值时触发资源策略 |
| 补足目标 | 一次补给希望达到的库存数量 |
| 等待资源 | 原执行保留目标，等待实物资源补充及重新校验 |
| 检查点 | 支持恢复的业务保存的进度、身份、库存与责任信息 |

## 谁触发，谁恢复

旅行和库存组件在支持的边界调用资源策略。策略判断资源不足时创建子 Flow，由当前父执行推进。子操作完成并结清责任后，父执行继续原来的目标及进度。

补给可能移动 Bot 的位置。`TravelToFlow` 在维护结束后重新检查到达条件：仍在目标位置时继续确认；已离开时从实际位置重新进入路线选择。原执行的累计时间、失败来源和补给预算继续保留。

```text
父操作准备继续
  → 检查资源策略
  → 推进补给子操作 → 结算库存与临时设施
  → 从 Bot 实际位置恢复父操作
```

`ResourceMaintenance` 管理活动资源类型、耗时和次数，限制同类递归维护。燃料维护中限制食物外出补给；可以完成的本地操作由策略决定。父操作的已取物资、借盒及交付责任在补给期间继续保留。

## TaskFireworkSupply

水位、预测与起飞检查见[烟花储备与补给](../navigation/fuel)。数量的共用语义见[库存要求与水位](./stock)。

默认 `FIXED` 低于 1,728 发触发，目标为 3,456 发。`AUTO` 可使用行程预测与安全系数。策略统计可消费的散装和携带盒内燃料，预留交付货物继续受保护。

外出获取复用 `ReplenishSuppliesFlow`，上次实际成功取货的来源作为回退；现成燃料不足时可尝试 `ProducePropulsionFuelFlow`。空中检查等待安全落地；水中且背包操作已结算时，可以直接开始通用取货导航，由导航与容器流程选择可交互站位。补给后结清责任，父操作从 Bot 的实际位置恢复。

安全位置仍不足时，`TravelFuelWait` 使原执行进入 `WAITING_FOR_RESOURCE`，报告缺量、维度、脚位和原因。新增普通推进烟花达到下限后重新校验。带爆炸效果的烟花排除在推进燃料之外。

同一来源的取货批次会先完成，再判断是否继续前往其他来源。当前来源足量时按补足目标取货；容量或来源稀缺时可在结算后以下限判断是否继续。

## TaskFoodSupply

`FoodPolicy` 用 `foodWhitelist`、普通物品组件和营养值筛选食物。默认白名单包含普通食物，金苹果等贵重或有毒食物由默认名单排除，用户可以配置名单。

Bot 饥饿不满且不高于 18，或受伤、饥饿不满且饱和度不高于 1 时，尝试进食。安全边界要求落地、身体在液体之外、结束飞行和物品使用、容器菜单及合成原料已结算。

优先通过 `EatCarriedFoodFlow` 吃散装食物；盒内食物复用 `UnpackCarriedMaterialsFlow` 拆取；需要外出时通过 `ReplenishSuppliesFlow` 获取符合策略的食物。允许外出补给时，散装储备的营养值最低为 32，目标为 80。

可选储备没有来源而 Bot 尚无需进食时，继续原操作，并在需要进食后重新考虑补给。实际饥饿无法满足、库存不一致或借盒未归还时，保留对应失败或恢复责任。

食物通过通用库存要求维护：`foodSupplyThreshold=32`、`foodSupplyTarget=80`，单位为营养值。运输准备与收集复用相同的食物、烟花策略及执行模式。

## 容量与上下文

容量流程按下一次取货、合成或施工的空位要求整理库存；[容器取货与潜影盒](./containers#容量与分批)介绍分批机制。

调用者决定给子操作提供哪些维护服务。同一次材料执行的运输准备与实际获取共享维护上下文、预算和上次成功烟花来源。`AcquireMaterialsFlow` 在获取和返回期间挂接食物与烟花策略；联合施工入口结束获取后进入独立施工阶段。接入范围见[施工物资与补给](../construction/supplies#补给触发与恢复)。

## 预算范围

维护次数、累计活动 tick、父流程补给余量和明确挂起具有不同计数范围。数值与计算方式见[预算](../navigation/budgets#补给预算与时间余量)。

## 等待、取消与恢复

| 情况 | 后续处理 |
| --- | --- |
| 维护完成 | 父操作继续，必要时按新位置重建旅行 |
| 等待资源 | 保留当前执行，观察新增资源并重新校验 |
| 用户取消或中断 | 处理已启动子操作及清理责任；中断取消原任务 |
| 正常关服后恢复 | 支持检查点的业务核对 Bot 身份、实物库存和剩余责任 |
| 异常退出或清理未结 | 报告阻塞原因，先核对状态再恢复 |

一次提交返回的任务 ID 用于查询和控制该次执行。检查点业务的恢复条件及指令见[恢复与排错](../guide/recovery)；忙碌 Bot 的拒绝、排队与中断语义见[执行控制与队列](../reference/task-control)。
