# 观察与异常处理

寻路以已观察的地形、允许的交通方式和有限搜索预算推进。异常处理保留实际位置和业务责任，由对应层级决定重规划、换源或等待。

## 世界记录与现场观察

Atlas 保存容器和传送设施的世界事实。实际移动需要区块中的碰撞、支撑、液体和交互几何；记录中的来源可能位于尚未加载的区域。

导航在请求范围内等待或推进地形观察，并核对到达现场后的状态。未观察到完整几何时，失败证据会保留未知地形信息。库存记录、搜索结果和实时碰撞分别影响来源是否可用。

## 预算的归属

搜索会话、局部导航、旅行与补给分别持有自己的限额。计时单位、默认数值、父子截止点和耗尽处理详见[预算](./budgets)。

## 异常由谁处理

| 现象 | 负责层级 | 典型后续 |
| --- | --- | --- |
| 局部边被挡或执行偏移 | `LocalNavigationFlow` | 观察当前位置，在剩余预算内重规划 |
| 起飞或着陆失败 | 飞行及区域接近组件 | 受限恢复、选择可用候选或报告失败 |
| 传送入口受阻 | `PortalJourneyFlow` | 排除入口或航段，尝试允许的替代 |
| 意外维度变化 | `TravelToFlow` | 从实际维度重规划，最多三次 |
| 缺少烟花 | 当前旅行拥有的资源策略 | 补给或进入资源等待 |
| 来源仍无法访问 | 收集业务 | 记录坐标，换源或报告缺料 |

“不可达”表示该策略与预算内未能到达。上层可以采用替代来源或用户协助，具体行为取决于业务结果契约。

## 安全与地图修改

导航检查人物碰撞、落脚和允许的交通方式。普通旅行按现有世界寻路；需要挖通、搭桥或隔水时，由有修改范围授权的施工业务提供相应能力。

`netherRoofOnly` 等活动限制会排除部分航段。水、落差和攀爬还受当前能力及搜索策略控制；限制见[局部寻路](./local#搜索策略)和[配置选项](../reference/config)。

## 诊断证据

查看执行 ID 的状态、实际维度、Bot 脚位、目标条件、搜索预算和失败坐标，再结合现场区块、碰撞与容器内容核对。

Trace 记录调用和观察信息，日志及真实世界状态用于交叉验证。[恢复与排错](../guide/recovery)介绍检查点恢复与状态查询。
