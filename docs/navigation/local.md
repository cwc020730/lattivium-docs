# 局部寻路与移动

局部寻路在当前维度搜索可以执行的移动路径，并逐段控制 Bot。它用于最后接近目标、容器交互站位、施工走位及较短行程。

## 请求、目标与结果

| 类型 | 含义 |
| --- | --- |
| `NavigationRequest` | 搜索参考位置、候选站位或探索目标、搜索策略 |
| `PathGoal` | 判断一个脚位是否满足完成条件 |
| `SearchPolicy` | 搜索会话节点预算、每 tick 展开量、允许交通方式、落差与部分路径策略 |
| 路径节点 | 搜索选中的可到达位置 |
| 路径边 | 连接相邻节点的一种具体移动动作 |
| `NavigationResult` | 实际脚位、可选到达节点、访问节点数与路径长度 |

探索目标可以表达“任意满足安全放盒条件的站位”。固定候选目标表达“这几个已经筛选的交互站位之一”。调用者选择适合业务的目标契约。

## LocalNavigationFlow

**输入：**`NavigationRequest`，或由命令生成的当前维度目标脚位。

```text
观察起点与目标
  → 按搜索预算展开路径
  → PathEdgeExecFlow 逐段执行
  → 核对实际位置与目标
  → 必要时从当前位置在剩余预算内重新规划
```

规划和移动分别有累计 tick 预算。重新规划保留这两个计数器与路径边重复访问约束；新的 A* 会话具有自己的节点额度。

分 tick 搜索每次继续时，共享规划器核验真实脚位能否进入原选定起点，不能只确认附近节点可站立。地面需要连续支撑与身体净空；水面、水下和攀爬分别消费已有介质几何。虚拟返程规划使用明确传入的未来脚位，不继承 Bot 当前是否着地的状态。起点失效时丢弃旧会话，并继续累计已用规划时间和展开量。

实时身体暂时没有可进入的起点，且尚未着地或实际身体所在格有水时，搜索保持 pending，等待原生物理形成可执行起点。浅水中的底部接触不能单独证明脚位已稳定；水格观察只允许有界等待，不证明路线可进入，也不授予水下移动权限。永久无合法起点仍消耗原规划和整体预算，并正常超时或取消。虚拟起点不等待实体落稳，无准入时直接拒绝。采用延迟路径和开始实际首边前都由同一 owner 复核；空路径进入终态对齐后，由原目标和对齐子流程核验，不继续套用出发检查。

等待时的姿态也由共享导航维护。深水表面保留原生浮力输入，已配置的水下起点使用水下图；脚下有完整实底、脚位为水且上一格为空气的浅水，复用共同水体几何的涉水分类，释放等待用的跳跃输入，让原生物理落稳。持续跳跃可能将身体顶在低顶下，使原本可进入的起点失效。涉水分类只决定等待姿态，后续仍须通过严格起点准入与碰撞检查；它不证明路线或抵达，也不刷新任何预算。

规划与水面扫掠使用共享几何中的原版声明姿态尺寸，站立、蹲伏各有明确合同。它们不另写近似碰撞箱，也不借用假人当前较小的游泳身体来证明站立通道可行。原版允许的贴顶接触与真实碰撞分别判断；实际姿态的局部操作继续核验原生身体。

重规划先结算持有输入的子流程、直接动作与路径边，再丢弃它们的引用。取消并不等于清理成功；清理失败禁止接管新移动。新搜索不刷新整体期限或重复访问额度。途中地形变化继续由原有路径执行核验处理。

水边的目的地也按当前原生状态核验。规划时在水中的目标退水后，Bot 只有在原目标脚位和高度真实落地、共同地面准入通过，且实际身体净空与支撑安全时才可完成；缺支撑、身体接触熔岩或传送门、未知区块不会因退水而变成成功。仍在水中的移动继续使用原水面或水下抵达合同，不增加施工专用重试或预算。

允许部分路径时，可先执行朝目标推进的路径前缀，再观察新区域继续规划。整体成功仍要求满足原目标；必须先证明完整路径的操作可以使用 `requiringCompletePath()` 策略。

## 到达与操作站位

普通调用方通过 `LocalNavigationFlow.toExactFeet` 请求到达一个脚位，或通过 `toGoal` 请求满足交互目标。导航统一选择已有步行、跳跃、游泳、攀爬和鞘翅能力，实际装备、碰撞和生存条件决定哪些方式可用。挖掘、建造或开箱的任务类型本身不增加全程干地、最低高度或禁飞条件。最低挖掘站位只在任务明确声明时生效；分层任务标签不会自动增加高度限制。明确配置的交通限制和设施路线合同仍生效。

`BlockPlacementGoal` 判断目标、支撑面、实际射线与身体站位；`ApproachBlockPlacementFlow` 统一负责到达与近距离对齐。普通放置、水格填充和水上平台使用这个入口。授权修改哪些方块、临时物品必须回收，以及操作完成后的返回位置，仍由任务明确提供；这些事实不替代导航决策。

薄支撑使用实际碰撞面的高度，睡莲、地毯和半砖的脚位不会再同时注册为上下两个节点。水下节点使用游泳高度，不继承下方半砖的支撑高度。普通水上平台的登板与返回复用局部导航。

旅行抵达的部分高度地面检查复用规划器的目标脚位解析，不再自行假定目标的上一格。泥土路径等实际支撑高度必须处于原目标列，遵守请求策略和最低脚位高度，并由共同几何核验真实身体的连续支撑与净空；邻列可站、不同楼层或未计划的传送门交叉不能代替抵达。这项修复没有改变既有的近距离抵达容差。

默认返回点由共享规划器解析当前真实起点，并核验该节点也可作为目的地。地面、水面和已启用的水下节点使用同一合同；调用方不再追加地面专用对齐判断。干燥下落中的身体不会冻结邻近落点，潜水开关仍约束水下节点；允许离开已经占用的传送门，并不允许把门内节点保存为返回目的地。

地面边在离水前的居中和移动也使用共享的流水补偿。输入组件依据身体实际入水状态选择控制强度；流水中允许完整原生移动输入，离水后恢复原有干地微调并清除补偿。路线准入、跳跃判据、居中精度和原执行预算保持原合同；施工和回收调用方无需提供另一套抗水流规则。

`CollectMiningDropsFlow` 使用 `ItemPickupGoal` 请求到达真实物品的接触位置，再核验数量、组件和绑定的实体 UUID，最后通过同一导航返回。默认出程使用 `NavigationRequest.requiringReturnTo(...)`，由同一规划器先核验当前世界的回程；这不保证以后地形、物资或生命状态保持不变。若组合流程必须先建立踏步才能返回，它通过 `withCallerOwnedReturn()` 明确承接返回义务，先拿取回执，再完成已授权踏步并调用共同导航。水下拾取也使用这条路径。普通物品嵌入方块碰撞体时交由 BEST_EFFORT 记录损耗。海绵先通过共享挖掘合同尝试站在其上方移除，确认下方有安全落脚处；真正无法回收的原生掉落由同一个拾取子流程按有界 BEST_EFFORT 记入损耗，保留实体 UUID、数量、组件和原因。损耗不计为回收或烘干，取消与库存异常不授权损耗；工具和盒仍保持严格保护。

共同 `ContactGoal` 表达需要原生接触的区域。导航负责终点对齐、净空允许的原生跳跃及落稳，不把这些输入控制交给拾取调用方；取消后由同一导航清理输入，后续请求在规划前处理实际空中姿态。接触结果不能替代物品数量、组件和 UUID 回执。

水面和水下普通边只证明实际到达图节点；精确终点交接由导航核验居中及低速姿态，避免每格停车。跳入水面时，即使已经经过目标坐标，仍须消除下坠动量并在可呼吸的水面落稳，随后才交给挖掘等操作。操作本身的射线与授权仍由交互系统核验。固定点可以执行验证过的路径前缀，但整体成功仍要求原目标；明确要求事前完整往返的请求继续采用完整路线准入。目标在交接期间变化时，未完成的子流程必须失败并清理，不能跳过成成功。

水下挖掘的进入、下降和返回也请求共同导航。`WaterPathEdgeExecFlow` 使用原版朝向、前进及冲刺游泳执行三维水边；头部露出水面时先用原版潜行下潜，输入不能同时保持冲刺与潜行。抵达后只进行交互所需的局部对齐，仍要验证真实身体、射线和作用权限；对齐进度不能截断已经合法开始的原生挖掘。

共同导航与水下挖掘通过 `WaterBreathing` 判断当前氧气准备，通过 `RestoreAirFlow` 请求同一个导航到达可呼吸位置，再等待原生氧气实际补满。低氧气不能反过来禁止逃生移动；关闭水下能力时也不能走私有浮升旁路。当前开放水柱的返回余量按原生 tick 估算，不能视为有遮挡路线或随机水下呼吸附魔的存活保证。短控中的点到达、取消、实际补气和深水操作回归仍分别核验，不能替代完整实场验收。

脚手架准备中的局部清理可声明一个本次清理不会破坏的真实交接脚位。共同支撑几何核验移除后支撑仍维持当前脚高，不能仅因更低处还有半砖就认定交接可用；清理结束后通过普通点导航实际返回，检查点保留相同目标并在恢复前重验。这个交接只结束局部阶段；还未建立的脚手架不能被当成已有出口，父流程仍须建立并核验整根脚手架通行。

## 路径执行组件

| 组件 | 负责的移动 |
| --- | --- |
| `GroundPathEdgeExecFlow` | 地面行走、台阶与支持的落差 |
| `DoorPathEdgeExecFlow` | 可交互门的通过 |
| `WaterPathEdgeExecFlow` | 水中路径段 |
| `ClimbPathEdgeExecFlow` | 受支持攀爬结构上的移动 |
| `ParkourPathEdgeExecFlow` | 规划允许的跳跃段 |
| `ShortElytraHopPathEdgeExecFlow` / `ElytraPathEdgeExecFlow` | 受策略允许的鞘翅路径段 |

各段依据碰撞、站位、液体、设备和控制条件执行。寻路依赖已有世界几何；挖掘、搭桥和施工授权由相应业务流程提供。

候选站位使用玩家的原版碰撞上下文，并投影到候选的实际高度。脚手架等碰撞形状依赖实体位置，不能用无实体检查先否决，也不能借用玩家当前高度判断远处或更低的候选。地面与攀爬的身体检查消费同一几何合同；挖掘和放置复用共同站位判断，仍分别核验操作射线、作用授权及移除脚下支撑的安全性。

身体干燥且有真实碰撞支撑时，脚下支撑块含水不等于身体浸水。共同地面准入按身体与流体的实际交集判断；身体进水、没有碰撞支撑、岩浆和危险方块仍会拒绝，不由水路或施工调用方另设例外。

梯子与脚手架支持上升和受控下降。Bot 可以从柱顶上方的空气格进入下降路径，在连续柱体内下降，再走到经过碰撞和支撑检查的出口。水柱和上升气泡柱用于上升；施工流程负责先建立所需通道。

水柱、登岸基础和水面/水下挖掘均使用共同导航及空气准备；旧 `SwimToDeckFlow`、`SwimToOpenSurfaceFlow` 私有移动已删除。禁用水下能力时不能走另一条浮升旁路。`BuildWaterLandingFlow` 只声明两格基础和操作顺序，逐格调用共同放置接近；不会额外填充内部水格。取消或第二格受保护时保留第一格的真实放置和材料扣减回执。

水面局部对齐按沿途每一列的实际水位判断连通，水格高度可以不同。身体检查覆盖当前高度到目标高度的完整移动包络，包括偏离格中心的肩部；未加载区域、碰撞、岩浆、传送门或干涸断点会明确拒绝。较低流动水上的移动使用同一水平控制与原生浮升，不为回收、挖掘或起飞另设水路。

水下边的途中姿态与终点姿态分开：终点是开放水面，不代表中途可持续上浮。执行器保留规划器校验过的水下通道，到实际目标列后才交接水面姿态，避免在网格或其他遮挡下提前上浮。精确抵达、空气预算及取消输入仍由共同导航负责。

水面对齐统一按原生入水和眼部状态处理抵流水反馈与上浮；已处于可呼吸的目标高度时不会仅因下方有水而继续跳跃。脚位须达到明确请求的水面高度，并处于共同水面几何包络内；位置与速度须连续稳定，再核验调用方的交互条件。通用垂直速度检查由对齐器负责，挖掘射线、放置和物品接触条件仍由各自操作提供。需要先上浮再跨过浅水岸台时，公共导航规划并执行该路线；局部对齐不会绕过低位身体碰撞检查。

水下水平路径包括一格边，都遵循已校验的走廊：实际脚位偏离中心线时，共享水边执行器先回到走廊再前进，避免朝远端直接斜游而撞上邻接方块。垂直边仍使用三维目标；水面浮升、空气预算、碰撞及取消清理合同保持一致。

流动水中的水平控制会保留有界的抵流校正。前视目标向前移动、暂时超出积分范围时，只暂停新的积分，不清空已有校正；离开启用的介质时才清空。水边、水面局部对齐和水下姿态使用同一控制组件，调用方不另加抵流策略。真实浅水失败的有限录制几何已通过直接水边和公共导航回归，但这不代表湿地整场验收已经完成。

短距离鞘翅路径直接消费规划器选定的起飞通道与落点。水面浮升产生水平偏移时，引导朝已选垂直通道修正；抵达目标列后使用共同飞行下降控制，接近底面才解除滑翔。进入落地阶段与最终成功分开：成功仍须原生着地、位置和高度核验。这里使用既有辅助飞行速度控制，不是完全无辅助的原版飞行；施工调用方不另外选择起飞或落地规则。

## 搜索策略

默认 `SearchPolicy` 的每次 A* 搜索会话节点展开上限为 8192，每 tick 上限为 16；它还声明飞行、深落差、部分路径和最低脚位高度等限制。实际执行采用分 tick 推进与时间预算。

`navigationAllowUnderwater` 默认 `true`，供当前水下作业使用；设为 `false` 时不生成水下边。调用可以用 `SearchPolicy.withUnderwater(false)` 进一步禁用，不能绕过全局禁用。当前不自动判断水下呼吸药水及其剩余时间。

燃料获取可使用禁止飞行的策略，以保证该段移动不依赖尚未拿到的烟花。复杂洞穴和长距离纯步行仍受路径规模及执行预算约束，具体计数范围见[预算](./budgets#a-搜索预算)，失败处理见[观察与异常](./recovery)。
