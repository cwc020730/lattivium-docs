# 局部寻路与移动

局部寻路在当前维度搜索可以执行的移动路径，并逐段控制 Bot。它用于最后接近目标、容器交互站位、施工走位及较短行程。

## 请求、目标与结果

| 类型 | 含义 |
| --- | --- |
| `NavigationRequest` | 搜索参考位置、候选站位或探索目标、搜索策略 |
| `PathGoal` | 判断一个脚位是否满足完成条件 |
| `SearchPolicy` | 搜索会话节点预算、每 tick 展开量、允许交通方式、落差与部分路径策略 |
| 路径节点 | 搜索选中的可到达位置 |
| 路径边 | 连接相邻节点的一种具体移动动作 |
| `NavigationResult` | 实际脚位、可选到达节点、访问节点数与路径长度 |

探索目标可以表达“任意满足安全放盒条件的站位”。固定候选目标表达“这几个已经筛选的交互站位之一”。调用者选择适合业务的目标契约。

## LocalNavigationFlow

**输入：**`NavigationRequest`，或由命令生成的当前维度目标脚位。

```text
观察起点与目标
  → 按搜索预算展开路径
  → PathEdgeExecFlow 逐段执行
  → 核对实际位置与目标
  → 必要时从当前位置在剩余预算内重新规划
```

规划和移动分别有累计 tick 预算。重新规划保留这两个计数器与路径边重复访问约束；新的 A* 会话具有自己的节点额度。

允许部分路径时，可先执行朝目标推进的路径前缀，再观察新区域继续规划。整体成功仍要求满足原目标；必须先证明完整路径的操作可以使用 `requiringCompletePath()` 策略。

## 路径执行组件

| 组件 | 负责的移动 |
| --- | --- |
| `GroundPathEdgeExecFlow` | 地面行走、台阶与支持的落差 |
| `DoorPathEdgeExecFlow` | 可交互门的通过 |
| `WaterPathEdgeExecFlow` | 水中路径段 |
| `ClimbPathEdgeExecFlow` | 受支持攀爬结构上的移动 |
| `ParkourPathEdgeExecFlow` | 规划允许的跳跃段 |
| `ShortElytraHopPathEdgeExecFlow` / `ElytraPathEdgeExecFlow` | 受策略允许的鞘翅路径段 |

各段依据碰撞、站位、液体、设备和控制条件执行。寻路依赖已有世界几何；挖掘、搭桥和施工授权由相应业务流程提供。

梯子与脚手架支持上升和受控下降。Bot 可以从柱顶上方的空气格进入下降路径，在连续柱体内下降，再走到经过碰撞和支撑检查的出口。水柱和上升气泡柱用于上升；施工流程负责先建立所需通道。

游泳登上已有平台由 `SwimToDeckFlow` 处理：先恢复到可呼吸的水面，再靠近出口，直到实际站在干燥、完整支撑的平台上才成功。它不建平台，也不清理障碍。时限依据起点到平台的水平距离与需要上升的高度计算，保留至少 400 tick；不能把从远处岸边进场的游泳当作贴着平台的一次短跳。

## 搜索策略

默认 `SearchPolicy` 的每次 A* 搜索会话节点展开上限为 8192，每 tick 上限为 16；它还声明飞行、深落差、部分路径和最低脚位高度等限制。实际执行采用分 tick 推进与时间预算。

燃料获取可使用禁止飞行的策略，以保证该段移动不依赖尚未拿到的烟花。复杂洞穴和长距离纯步行仍受路径规模及执行预算约束，具体计数范围见[预算](./budgets#a-搜索预算)，失败处理见[观察与异常](./recovery)。
