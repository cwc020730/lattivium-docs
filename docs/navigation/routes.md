# 路线与跨维度

路线连接地点和维度，帮助旅行选择接近与穿门顺序。Atlas 提供已记录传送设施，Bot 的旅行规划器结合实时状态和策略决定如何使用。

## 路线数据

| 术语 | 具体含义 |
| --- | --- |
| 路线节点 | 具有类型、维度和坐标的已知地点 |
| 路线边 | 连接两个节点的移动或传送关系，带估计权重 |
| 传送转换 | 指定从哪个维度的地点进入，预期到哪个维度的地点 |
| 入口候选 | 可用于实际接近并进入传送设施的位置 |
| 实际出口 | 游戏传送后观察到的 Bot 位置 |
| 出口清离 | 离开再次触发传送的空间，建立后续移动边界 |

`TravelRoute` 保存不可变节点和边。入口、出口及连接关系作为规划提示，执行时仍核对设施和实际传送结果。

## 同维度绕行

`TravelToFlow` 可以比较当前维度直达与跨维度绕行。长距离主世界行程可能经过下界，再返回主世界接近最终目标；两种路线根据已知传送网络、行程成本和活动范围筛选。

来源规划使用旅行估价选择库存；实际旅行拥有路线执行和替代尝试。这两层共享事实，各自承担来源分配与到达的职责。

## PortalJourneyFlow

**输入：**路线提示、目标维度、选择参考点与搜索策略。

它选择入口及接近站位，调用区域接近或局部导航，实际进入传送设施，等待维度变化，观察出口并离开触发区。遇到已拒绝入口或航段时，在剩余预算内选择允许的替代。

**完成条件：**完成所选传送行程并清离出口。最终业务目的地由 `TravelToFlow` 接着核验。

显式命令中的 `entrance` 与 `exit` 指定路线提示，`target` 帮助选择方向。日常目标移动使用 [TravelToFlow](./targets#traveltoflow)；完整入口参数见 [Flow 参考](../reference/flows#portaljourneyflow)。

## 预测与现场

下界门的维度比例和附近既有门参与出口预测。记录的门可能被拆除，或实际传送落点与预测不同；旅行以观察到的维度、位置和有效入口继续判断。

目标维度变化、入口受阻或无法清离出口分别可能导致重规划或失败。耗尽预算后的结果保留原因和坐标。

## 活动范围

`netherRoofOnly=true` 将下界脚位限制为 Y≥128，并过滤屋顶以下或未知的出口。结构排除及库存保护主要作用于来源选择；传送与移动策略作用于旅行可用航段。相关配置见[配置选项](../reference/config)。
