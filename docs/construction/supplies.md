# 施工物资与补给

施工使用两类物资：设施和挖掘要消耗的材料，以及维持 Bot 行动的烟花、食物和运输容量。前者由场地计划计算需求，后者由补给策略在操作边界检查。

## 从场地到物资需求

`PrepareAndExcavatePerimeterFlow` 根据自主补给开关选择开工方式：

| 接入方式 | 开工前行为 |
| --- | --- |
| `autonomousSupplies: false`（默认） | 使用 Bot 已携带的施工物资，直接开始设施建设 |
| `autonomousSupplies: true`，或 Java 调用 `withAutonomousSupplies(mode)` | 勘察场地，调用 `AcquireMaterialsFlow` 获取需求，返回启动位置，再开始设施建设 |

注册命令也支持自主补给开关、`mode`、`sealBottom` 和 `drainageMode`，以及区域、输出盒数量和净空高度。入口和参数见 [Flow 参考](../reference/flows#prepareandexcavateperimeterflow)。

需求来自 `PerimeterInfrastructurePlan` 和现场液体观察：

| 物资 | 当前计算方式 | 用途 |
| --- | --- | --- |
| 沙子 | 围墙用量、两根井道隔水柱，以及起始平台补齐量；复用已验证沙墙时扣除围墙用量 | 周界封水与井道隔离 |
| 白色混凝土 | 设施用量、可选封底预算，再加最大单层液体处理需求 | 道路、平台、填液体与临时隔墙 |
| 脚手架 | 井道计划用量 | 垂直通行 |
| 箱子、空潜影盒 | 两个箱子，以及工作站计划中的输出盒数量 | 工作站仓储与产物容器 |
| 烟花 | 共用 FIXED 或 AUTO 水位策略 | 飞行与后续航段预留 |
| 食物 | 共用食物策略和库存要求 | 真实饥饿下进食与储备 |
| 海绵、熔炉、煤 | 海绵模式的湿层需求：一块干海绵、一个熔炉，煤按单层最大格室数备齐 | 吸水、回收与工作站烘干 |

物资预算逐层观察液体，并按物品取**各层需求的最大值**。湿层的填料需求为该层液体格数加 64 格余量；海绵模式再加该层网格隔墙格数。干层不增加液体处理预算。这里计算的是单层周转储备，施工中材料不足时仍通过共用获取链续补，不能理解为整场总消耗上限。

当前海绵烘干采用单块事务：每次吸水并回收湿海绵后，Bot 返回工作站，准备一块湿海绵、一个熔炉和一份煤，烘干后回收干海绵及熔炉，再继续施工。因此燃料预算按烘干次数计，每次消耗一份煤；海绵与熔炉则循环使用。

设施混凝土预算为工作站地板格数加两格；启用封底时再加整个底面格数。封底实际保留已有的合格实心方块，预算因此可能有剩余。运输盒容量由通用库存准备流程维护，和要放在工作站的输出盒分别管理；施工需求表没有额外固定的 `outputBoxes + 1` 运输盒规则。

## 通用获取链

施工把需求转换成“物品 ID → 数量”，交给 `AcquireMaterialsFlow`。它复用原理图供给所用的规划、取货、拆盒和合成组件。

```text
场地勘察 → 施工需求表
  → AcquireMaterialsFlow
    → AtlasSupplyLoadFlow：来源分配、配方展开、运输准备
    → AcquireProductionFlow：收集、必要合成、数量结算
    → TravelToFlow：返回启动位置
  → 设施建设 → 逐层清场 → 返回工作站 → 实场核验
```

`AcquireMaterialsFlow` 的结果是 Bot 携带的材料，后续用途由调用者负责。`AtlasSupplyTask` 使用同一条获取链，并追加实物交付。两者的共用组件见[材料收集与合成](../guide/supply#共用组件)。

## 补给触发与恢复

| 资源 | 检查者 | 触发条件 | 完成后继续的位置 |
| --- | --- | --- | --- |
| 烟花 | 旅行流程与 `TaskFireworkSupply` | 可用普通烟花低于配置的 FIXED 或 AUTO 水位 | 原旅行目标 |
| 食物 | 安全操作边界与 `TaskFoodSupply` | 饥饿需要进食，或允许外出补给时储备不足 | 原取货或旅行操作 |
| 容量 | 运输准备与库存整理流程 | 计划运输或下一次操作所需空位不足 | 原库存操作或施工阶段 |
| 施工材料 | `AcquireMaterialsFlow` 的数量结算 | 开工前需求尚未全部满足 | 继续获取；全部满足后进入施工 |

补给作为当前执行的子操作推进。父操作保留目标、进度与物品责任，子操作结束并完成必要清理后，父操作继续。`ResourceMaintenance` 管理活动补给类型与累计预算，限制同类递归补给；燃料补给期间限制额外的食物外出行程。

取货阶段提供烟花与食物策略。设施建设使用已经携带的物资；逐层挖掘通过 `ExcavationSupplies` 接入共用的 `TaskFoodSupply`、`TaskFireworkSupply` 和 Atlas 来源查询，并在安全边界执行补给行程。维护时统一观察 L0、L1 和自有 L2 运输盒中的物品，挖出的货物装盒后仍保持预留。各阶段使用自己的维护生命周期，共用资源策略与获取组件，详见[资源维护](../guide/supply#资源维护)。

## 开工边界

自主获取要求需求全部满足且库存责任结清，随后返回启动位置。物资仍缺失时，流程记录物品、数量和失败来源，设施阶段保持未开始。

食物与烟花由共用库存策略维护。海绵模式把海绵、熔炉和燃料纳入湿层需求；不适合安全使用海绵的格室仍使用实心填料，并分别记录。自主获取完成后，由 `AcquireMaterialsFlow` 明确安排返回启动位置，货物保留在 Bot 身上。这次返回是施工取货流程的业务要求；`TravelToFlow` 本身执行传入的单向目标，不会给所有旅行自动追加往返行程。

烟花补给优先取现成普通烟花，库存不足时尝试有限合成。无法满足出发预留时，在安全的落地与库存结算边界进入 `WAITING_FOR_RESOURCE`，报告缺量及 Bot 位置；补充普通烟花并重新通过库存、路线校验后继续原目标。

## 拆盒与材料续用

来源箱中的带货潜影盒由借盒流程管理：取出、放置、精确拆取、回收并归还余料。Bot 已携带的运输盒由通用潜影盒访问与库存整理组件管理，可为沙子、填料、烟花和食物腾出散装容量。

施工子流程在材料不足时按自身契约读取携带库存、拆取或报告短缺。开工前的总量获取与施工中的分批拆盒分别拥有数量结算和容器操作责任。

普通挖掘产物使用配置的尽力回收策略。工具、潜影盒、海绵和库存一致性保留专门保护；回收策略见[清场](./clearing#产物回收)。

无损调试模式传递给取货与挖掘阶段的食物、烟花补给。来源库存保持原样，Bot 正常消耗取得的副本。
