# 建造

建造由场地布局、基础设施、清场和原理图施工组成。工作站负责物资存放，井道负责垂直通行，连接道路让 Bot 在两者之间移动。

![工地剖面：井道、永久连接道路、工作站和预定清场范围](/construction/site-section-zh.svg)

## 施工阶段

| 阶段 | 完成结果 | 说明 |
| --- | --- | --- |
| [布局与勘察](../construction/planning) | 固定井位、工作站和可施工路线 | 同时检查材料预算与修改范围 |
| [施工物资与补给](../construction/supplies) | 获得施工材料及运输容量 | 自主获取复用通用取货与合成链 |
| [井道](../construction/shaft) | 具有可靠根部和出入口的脚手架通道 | 实际验证上行与下行 |
| [连接道路](../construction/road) | 井口至工作站的永久通路 | 逐块搭建并检查人物净空 |
| [工作站](../construction/workstation) | 地板、容器与通行空间 | 从连接道路末端展开平台 |
| [清场](../construction/clearing) | 指定区域清空、产物有记录 | 按层执行，处理容量与液体义务 |
| [原理图施工](../construction/schematic) | 目标方块状态核验完成 | 读取原理图并执行已有施工能力 |

## 功能状态

区域清理和原理图施工有各自的[执行入口](../reference/flows)。场地准备使用井道、连接道路、工作站与平台放置组件。

`PreparePerimeterInfrastructureFlow` 对方形施工区先挖四边沟并填成沙墙，在一侧沙墙中建立隔水脚手架井，再建白色混凝土连接路和区外工作站。`PrepareAndExcavatePerimeterFlow` 在同一执行中完成这些设施和区内逐层清场。干燥场地也可使用 `PrepareSiteInfrastructureTask` 规划井道、道路和工作站。

两种封边整合入口默认从头施工。明确设置 `reuseSandWall=true` 时，先核验整圈沙柱的目标高度与干燥底座，再复用这圈完整沙墙，只免去墙体施工和对应沙子需求。井的内外隔水柱、脚手架、道路、工作站与内部清场仍要完成；部分沙墙、已有井或工作站不属于这一选项的恢复范围。`stagingAreas` 可提供已知拆盒位置的寻路提示，实际放置与交互仍由通用库存流程检查。这样的开发接续单独记录，不算从初始物资开始的整场自主验收。

## 连续施工流程

```text
勘察与物资需求
  → 获取物资并返回起点（启用自主获取时）
  → 四边挖沟、逐柱落沙封边
  → 隔水井心换成脚手架
  → 连接道路与工作站
  → 核验往返通行、整理背包空位
  → 从最高层开始：排水或填液体 → 挖除本层 → 核验干燥空气
  → 重复至最低层
  → 返回工作站，核验全区域与保留设施
```

每个阶段拥有具体完成条件。设施阶段检查实体方块与实际通行；清场阶段检查每层的空气和液体状态；最终核验同时检查设施及 Bot 的工作站返回位置。物资获取、施工和交付的职责分别见[施工物资与补给](../construction/supplies)与[材料收集与合成](./supply)。

## 执行层次

Task 管理业务进度、恢复与结果；Flow 编排一个可复用的操作过程；Action 执行具体动作。内部施工组件由上层任务传入已确定的布局及运行时依赖。

当前施工链使用的组件包括 `PrepareScaffoldAccessFlow`、`PreparePlatformFlow`、`PrepareWorkstationFlow` 和 `BuildBlockFlow`。各阶段页面说明它们的职责。可独立执行的类型与参数统一列在[执行入口](../reference/executables)。
