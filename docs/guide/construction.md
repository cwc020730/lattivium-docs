# 清场与建造

## 区域清理：会实际破坏方块

范围包含两端，属于 Bot 当前维度；每个维度轴最多 64 格，总体积最多 32768 格。
仓储坐标必须在范围外且互不重复，每处原生放置一个潜影盒，需自备有限空盒及工具。
无需也不会默认授予无限耐久效率 V：那是开发验收时的预置条件。

```text
/lattivium <Bot> exec ExcavateAreaFlow <minX minY minZ> <maxX maxY maxZ> <depotX depotY depotZ> [更多仓储三元组] [--seal <区外封堵三元组...>]
```

流程从上往下原生开挖，核对掉落与实际拾取，容量接近满时入库，最终确认目标体积为空且稳定无液体。
范围授权普通清场，不授权破坏机器、容器、传送门或区外地形；冲突会报告坐标。

## 液体和临时设施

内部水/熔岩可用有限填料清除，填料最终回收。普通含水方块可用空桶原生取水；满桶保留。
外部持续来水需要显式 `--seal` 授权紧邻区外的封堵点；永久挡水块保留，和内部临时填充分别记账。
不允许为达成“空区域”擅自改动范围外已有地形。

无鞘翅浅坑可用临时水柱：区域已完全清空、最多深 4 格和水平 8×8、完整封闭底部及四周、持有水桶并有可用坑沿。
放水、游出、收水后必须等待区域连续 100 tick 为空。
不覆盖水会蒸发的环境、任意深坑、未清空坑内的无飞行中途满包出入。
鞘翅场景会检查烟花储备，但储备足够不等于已经证明起降路线。

## 清场恢复

```text
/lattivium <Bot> exec ExcavateAreaFlow <taskUUID>
```

UUID 来自该清场任务 trace 的 `taskId`，不应把排队事件 ID 当成同一个编号。
检查点位于世界 `lattivium/excavations/`。恢复核对 Bot 身份、维度、库存、盒内收据和剩余义务。
当前格式 6，可读 4/5；不要编辑检查点绕过库存差异。补给中断可能需要人工检查，不能保证自动重放。

## 原理图建造 MVP

```text
/lattivium <Bot> exec BuildSchematicFlow <file.litematic> <x> <y> <z>
```

输入目录同材料供给，坐标是放置原点，维度为提交时 Bot 的维度。
流程读取受支持的有限原理图、补足缺料、旅行、勘察、逐块施工并核对最终方块状态。
这是有界 MVP，不是“任意原理图、任意场地、自动清场后必成”的承诺。
当前保留本来正确的方块；默认整区清空再逐层建造、顶部通行空间等是后续施工方向，尚非该入口的统一实现。
不要假定支持 Printer 凭空放置或忽略所有朝向。
