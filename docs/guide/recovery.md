# 恢复与排错

## 执行状态

用 `/ltv Worker tasks` 查询任务，再用 `/ltv Worker status <taskId>` 查看具体结果。调试面板中的 `position` 是 Bot 当前脚部坐标，`savedTasks[].position` 是保存检查点时的位置。

任务提交、取得物品和交付物品分别记录。供给终态应结合交付量、缺料量及剩余义务判断。

## 检查点

供给检查点位于世界 `lattivium/tasks/`。正常关服后，满足恢复条件、相同 UUID 的 Bot 重新上线且空闲时，恢复注册器尝试接续任务。库存差异、多个未解决任务或剩余义务会阻止恢复。异常退出遗留的运行中记录会标为 `BLOCKED`，供人工核对。

清场检查点位于 `lattivium/excavations/`，通过 `ResumeExcavation` 和清场 trace 中的业务任务 ID 恢复。恢复会核验 Bot、维度、库存、回执和剩余预算。

## 排错顺序

| 现象 | 检查内容 |
| --- | --- |
| Bot 忙碌 | 当前任务和队列；按需求选择排队或中断 |
| 清理阻塞 | `cleanupBlockedBy`、日志和现场剩余设施 |
| 查不到库存 | Atlas 索引状态、来源保护和结构排除策略 |
| 数量不符 | 容器实际内容和观察时间 |
| 寻路失败 | 维度、Bot 脚位、目标及搜索预算 |
| 恢复被拒绝 | 检查点原因、实际库存和未结义务 |

结合 trace、实体位置、容器内容和实际方块状态交叉验证。来源在预算内不可达时，供给流程会寻找替代，或报告缺料并完成其余义务。
