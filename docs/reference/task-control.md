# 任务控制

`/ltv` 是 `/lattivium` 的简写。下列命令默认需要权限等级 2，可通过 `commandPermissionLevel` 调整。

## 提交与排队

| 命令 | 行为 |
| --- | --- |
| `/ltv <Bot> exec <入口> <参数>` | 空闲时受理；已有活动任务、待执行队列或清理阻塞时拒绝 |
| `/ltv <Bot> enqueue <入口> <参数>` | 将任务加入队尾，按先后顺序执行 |
| `/ltv <Bot> interrupt <入口> <参数>` | 取消当前任务，将新任务放在待执行队列最前端 |

三种提交方式共用相同入口和参数校验，参数支持 JSON 对象及该入口的位置参数语法。受理消息包含 `task=<UUID>`、Bot 名称和初始状态。

每个 Bot 同时执行一个根任务，最多等待 32 个任务。等待期间保留任务 ID，执行预算与 trace 从任务取得执行位时开始。中断保留原有待执行队列；替换任务在当前任务清理完成后启动。

## 查询与取消

```text
/ltv Worker tasks
/ltv Worker status <taskId>
/ltv Worker cancel <taskId>
```

`tasks` 列出活动任务、队列和保留的终态历史，并显示 `cleanupBlockedBy`。`status` 返回指定任务的状态、描述和失败信息。查询范围限于指定 Bot。

取消待执行任务会直接将其标为 `CANCELLED`。取消活动任务会在调度 tick 执行清理，再发布终态。已完成的世界修改保留，借出的容器和临时设施按所属流程的清理逻辑处理。

## 清理阻塞

当前任务的清理或输入释放失败时，后续任务留在队列中，新提交也会被拒绝。检查日志、trace 和现场，处理剩余义务后执行：

```text
/ltv Worker acknowledge-cleanup
```

该命令确认已处理清理问题，释放输入并解除阻塞，允许队列继续执行。任务的失败记录仍会保留。

## ID 与恢复

任务 ID 跟踪本次提交，终态记录数量由 `terminalTaskHistory` 控制。队列存在于当前服务器进程内。正常关服时，已运行且支持检查点的任务由各自恢复机制保存；待执行队列在关服时取消。

`interrupt` 取消原任务。后续恢复使用该任务已有的[检查点机制](../guide/recovery)。清场检查点的业务 `taskId` 来自清场 trace，恢复命令使用此 ID。
